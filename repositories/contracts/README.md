# contracts

The wire contracts shared by the services: gRPC `.proto` files, the TypeScript generated from them, and the Zod schemas of the RabbitMQ events. Services include this repository as a git submodule (there is no shared npm package).

## What's here

- `proto/sales/<service>/v1/*.proto` - synchronous reads used by `orders-api`:
  - `catalog.proto`: `GetProducts` returns sale rules (pack factor, multiple-only, active) and the unit price from a price table.
  - `identity.proto`: `GetClient` (portfolio owner, effective price table with fallback flag, credit) and `GetSeller` (discount limit in basis points).
- `gen/ts/` - code generated by `ts-proto` (`nestJs=true`, `grpc-js`). **Committed on purpose**: services read it through the submodule, so only this repo needs the generator.
- `src/events/` - Zod schemas and inferred types for `OrderSubmitted`, `OrderApproved` and `OrderRejected`, plus the RabbitMQ patterns.

Conventions: money in integer cents, discounts in basis points (1% = 100), package `sales.<service>.v1`, missing entities answered with gRPC `NOT_FOUND`.

## Change a contract

```bash
pnpm install
# edit proto/...
pnpm lint          # buf lint
pnpm generate      # regenerates gen/ts (commit the result)
pnpm typecheck
pnpm test
```

Then, in each service, update the submodule pointer to the new commit. Any service still using a renamed or removed field fails to compile, which is the point of generating the types.

## Test

```bash
pnpm test          # Vitest: event schemas
pnpm check:generated   # fails if gen/ is stale (used by CI)
```

## Notes

- Node 24 and pnpm (via corepack). Install scripts are denied by default; only `@bufbuild/buf` is allowed (`allowBuilds` in `pnpm-workspace.yaml`) because it downloads its binary.
- Backward-compatible changes (new fields, new RPCs) stay in `v1`. A breaking change needs `v2`; `buf breaking` can check this against the previous commit.
